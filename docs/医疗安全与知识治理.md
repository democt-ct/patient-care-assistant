# 医疗安全与知识治理

## 回答边界

- 患者病历、就诊和处方的事实查询：仅陈述已检索到的记录，并显示其来源和日期。
- 健康宣教：应基于已审核的知识条目；缺少足够证据时明确说明不能确认。
- 个体化用药、剂量、停药/换药、漏服/过量和药物联用：不进行自由生成，提示患者联系开方医生或药师。
- 紧急症状：不进入普通问答，直接提示拨打 120 或前往急诊。

## 生成前安全门禁

`app/mcp/medical_safety_gate.py` 在 `run_agent_tool_query` 的 LLM 初始化之前执行。

| 命中类型 | 处理 |
| --- | --- |
| 紧急症状 | 直接返回急诊指引，不调用模型 |
| 高风险个体化用药/治疗决定 | 直接返回医生或药师核实指引，不调用模型 |
| 其他问题 | 进入原有意图识别与回答链路 |

门禁是确定性规则，不使用 LLM 做是否拦截的判断。规则命中会在响应中以 `medical_safety_gate` 记录，便于审计和评估。

## 知识条目准入

`memory_knowledge_chunks` 新增以下字段：

- `source_url`：权威原始链接或内部受控文档地址；
- `source_id`：已登记的知识源标识；
- `evidence_level`：证据/编辑等级；
- `review_status`：`unreviewed`、`approved`、`retired`；
- `reviewed_by`、`reviewed_at`：临床审核责任与时间。

创建 `approved` 条目必须提供 `source_id`、`source_ref`、`reviewed_by` 和 `reviewed_at`。读取、搜索和检索接口可传 `approved_only=true`，仅获得临床审核通过的条目。

上线前须执行 `migration/20260723_knowledge_review_metadata.sql`。新知识源先进入 `unreviewed`，由临床审核后才可标记为 `approved`；过期或撤回内容必须标记为 `retired`。

## 受控导入

知识源白名单定义在 `app/config/medical_source_registry.py`，当前包含药监药品信息、卫健系统规范、WHO 指导材料和医院内部审核内容。导入程序会验证 `source_id`、来源 URL 域名、来源类型和发布权限：

```powershell
python scripts/import_clinical_knowledge.py data/examples/clinical_knowledge.example.json --dry-run
python scripts/import_clinical_knowledge.py data/clinical_knowledge.json --apply
python scripts/import_clinical_knowledge.py data/clinical_knowledge.json --apply --publish
```

`--publish` 不是审核本身；它只允许已填好临床审核责任信息的 `approved` 条目写入数据库。默认导入不立即同步向量，避免导入期间下载或加载嵌入模型；需要时显式追加 `--sync-vector`。

## 过敏安全机制（五层防护）

> 原「患者过敏安全机制设计.md」，2026-08-04 并入本文。核心原则：**患者过敏史（绝对硬约束） > RAG 知识库（参考信息） > LLM 自身知识（通用医学常识）**。

### 问题场景

- **场景 A（已知过敏 vs 知识冲突）**：患者档案记录"阿司匹林过敏"，但 RAG 知识库推荐头疼标准治疗是阿司匹林。系统必须让患者隐私数据（过敏史）压过公共医学知识。
- **场景 B（未知过敏）**：档案未记录过敏史（`allergy_history` 为空）时，"不知道过敏"不等于"没有过敏"，不能无阻碍地自信推荐药物。

### 五层防护

| 层 | 位置 | 行为 |
| --- | --- | --- |
| 1. 过敏药物提取与传递 | `app/api/mcp_routes.py` `_parse_allergy_drugs` | 身份解析后从 `allergy_history` 解析过敏药物（词典匹配 + "对XX过敏"正则回退），经 `allergy_drugs` 贯穿生成链路 |
| 2. RAG 知识过滤 | `app/api/mcp_routes.py` `_filter_allergy_from_knowledge` | 检索知识块逐行剔除含过敏药物的条目 |
| 3. Prompt 硬指令 | `app/mcp/llm_router.py` | 已知过敏注入"绝不要推荐这些药物或同类药物"；未知过敏（`allergy_history_unknown=True`）注入"自然包含用药提醒"的行为指令，不输出独立提醒块 |
| 4. 回答后安全扫描 | `app/mcp/llm_router.py` `_check_allergy_safety` | LLM 生成后扫描回答中的过敏药物，命中即追加醒目安全提醒 |
| 5. 证据层冲突判定 | `app/services/evidence_policy.py` | 主档同时出现"过敏 + 慎用"判为需医生确认的边界冲突；药物教育问题不因不在证据包而被误拒 |

### 数据流

```text
mcp_agent_query → 身份解析 → 提取过敏药物 → 知识过滤 → run_agent_tool_query
  → Prompt 注入（已知过敏硬警告 / 未知过敏行为指令）→ LLM 生成 → 安全扫描 → 输出
```

### 边界情况

| 情况 | 行为 |
| --- | --- |
| 已知过敏（场景 A） | RAG 过滤 + Prompt 硬警告 + 输出扫描，三层全开 |
| 过敏史未记录（场景 B） | 注入"全面回应 + 用药提醒"行为指令 |
| 无患者绑定（general 模式） | 两者均不注入 |
| LLM 提到过敏药同义词/商品名 | 当前仅字面匹配，后续可引入同义词库（局限） |
| 过敏药不在已知词典 | 正则回退捕获"对XX过敏"模式 |

### 已知局限与扩展方向

1. 药物同义词/商品名匹配（如"阿司匹林" vs"乙酰水杨酸"）。
2. 药物类别推理（阿司匹林过敏 → 同类 NSAID 如布洛芬应联动，冲突用例已覆盖 NSAID 交叉风险提示）。
3. 过敏严重程度分级（休克 vs 轻度皮疹）。
4. 半匿名模式（仅手机号无完整档案）的未知过敏语义。
