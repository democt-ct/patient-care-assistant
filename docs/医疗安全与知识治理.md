# 医疗安全与知识治理

## 回答边界

- 患者病历、就诊和处方的事实查询：仅陈述已检索到的记录，并显示其来源和日期。
- 健康宣教：应基于已审核的知识条目；缺少足够证据时明确说明不能确认。
- 个体化用药、剂量、停药/换药、漏服/过量和药物联用：不进行自由生成，提示患者联系开方医生或药师。
- 紧急症状：不进入普通问答，直接提示拨打 120 或前往急诊。

## 生成前安全门禁

`app/mcp/medical_safety_gate.py` 在 `run_agent_tool_query` 的 LLM 初始化之前执行。

| 命中类型 | 处理 |
| --- | --- |
| 紧急症状 | 直接返回急诊指引，不调用模型 |
| 高风险个体化用药/治疗决定 | 直接返回医生或药师核实指引，不调用模型 |
| 其他问题 | 进入原有意图识别与回答链路 |

门禁是确定性规则，不使用 LLM 做是否拦截的判断。规则命中会在响应中以 `medical_safety_gate` 记录，便于审计和评估。

## 知识条目准入

`memory_knowledge_chunks` 新增以下字段：

- `source_url`：权威原始链接或内部受控文档地址；
- `source_id`：已登记的知识源标识；
- `evidence_level`：证据/编辑等级；
- `review_status`：`unreviewed`、`approved`、`retired`；
- `reviewed_by`、`reviewed_at`：临床审核责任与时间。

创建 `approved` 条目必须提供 `source_id`、`source_ref`、`reviewed_by` 和 `reviewed_at`。读取、搜索和检索接口可传 `approved_only=true`，仅获得临床审核通过的条目。

上线前须执行 `migration/20260723_knowledge_review_metadata.sql`。新知识源先进入 `unreviewed`，由临床审核后才可标记为 `approved`；过期或撤回内容必须标记为 `retired`。

## 受控导入

知识源白名单定义在 `app/config/medical_source_registry.py`，当前包含药监药品信息、卫健系统规范、WHO 指导材料和医院内部审核内容。导入程序会验证 `source_id`、来源 URL 域名、来源类型和发布权限：

```powershell
python scripts/import_clinical_knowledge.py data/examples/clinical_knowledge.example.json --dry-run
python scripts/import_clinical_knowledge.py data/clinical_knowledge.json --apply
python scripts/import_clinical_knowledge.py data/clinical_knowledge.json --apply --publish
```

`--publish` 不是审核本身；它只允许已填好临床审核责任信息的 `approved` 条目写入数据库。默认导入不立即同步向量，避免导入期间下载或加载嵌入模型；需要时显式追加 `--sync-vector`。
