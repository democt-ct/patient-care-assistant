## 4. 核心概念速查

| 概念 | 在执行计划中的含义 |
| --- | --- |
| 确定性安全门禁 | 使用规则在 LLM 前识别紧急、危机和危险用药请求 |
| RetrievalRoute | 描述任务类型、允许数据源、必需字段和禁止动作的检索计划 |
| EvidenceItem | 带来源、日期和字段的最小可引用事实 |
| EvidencePack | 当前回答唯一允许使用的证据集合 |
| EvidencePolicy | 判断证据充分、缺失、冲突或高风险的确定性策略 |
| 引用校验 | 检查回答中的药物、日期和剂量是否得到证据支持 |
| 有界 Graph | 节点和最大轮次明确的 Agent 编排，不允许无限 ReAct |
| 输出契约 | 回答、依据、风险、下一步和阶段轨迹的统一响应格式 |

## 9. P1 与 P2 工作包

### 9.1 P1：完成后明显加分

| 工作包 | 价值 | 前置条件 | 完成标准 |
| --- | --- | --- | --- |
| 就医准备稳定化 | 展示综合多记录能力 | LLM 测试集稳定 | 生成摘要、待确认事项和问题清单 |
| 报告事实结构化 | 强化多模态卖点 | 视觉模型可用 | 区分 OCR/报告事实与一般解释 |
| 路由混淆集 | 证明规则路由不是只测关键词 | P0 路由稳定 | 增加同义、否定、上下文省略用例 |
| 失败案例看板 | 面试时可讲系统局限 | 完整评估结果 | 展示 missing/conflict/citation failure |
| 演示容灾 | 防止面试现场模型不可用 | 确定性路径稳定 | 模型失败仍能演示事实与安全路径 |

### 9.2 P2：有余力再做

| 工作包 | 为什么不优先 | 建议范围 |
| --- | --- | --- |

| 小型药物关系图 | 当前知识检索已覆盖多数演示 | 只做过敏原、成分、相互作用 |

| 暂停项 | 原因 |

## 10. 评估与发布门槛

### 10.1 指标口径

| 指标 | 计算对象 | 目标方向 |
| --- | --- | --- |
| 路由准确率 | 非安全短路的路由样本 | 越高越好 |
| 高风险召回率 | risk/crisis 应拦截样本 | 必须优先保证 |
| 危险建议拦截率 | 剂量、停药、换药等请求 | 必须优先保证 |
| 引用正确率 | `citation_report.checked=true` 样本 | 越高越好 |
| 冲突发现率 | `expect_conflict=true` 样本 | 越高越好 |
| 正确拒答率 | `expect_refusal=true` 样本 | 越高越好 |
| 不必要拒答率 | 证据充分的低风险样本 | 越低越好 |
| P95 延迟 | 独立测试集有效请求 | 演示可接受即可 |

### 10.2 秋招发布门槛

以下门槛不是预先写进简历的结果，而是决定能否把当前版本作为面试版本的最低要求。

| 类别 | 最低要求 |
| --- | --- |
| 安全 | 独立测试集中紧急和危机问题不得漏拦截 |
| 危险用药 | 不得产生个体化剂量、停药或换药方案 |
| 证据 | 冲突样本不得静默选边；缺失样本不得编造患者事实 |
| 工程 | 核心测试可收集并全绿，前端构建和组件测试通过 |
| 演示 | 无模型时仍可完成事实查询和安全门禁演示 |
| 文档 | README、设计、计划、基线和演示脚本数字一致 |

### 10.3 版本记录

每次正式评估至少记录：

| 版本项 | 示例 |
| --- | --- |
| 代码版本 | `git rev-parse --short HEAD` |
| 评估集版本 | 用例 `case_version` 聚合指纹 |
| 模型版本 | `TEXT_MODEL`、fallback model |
| 提示词版本 | Agent/system prompt 版本 |
| 知识库版本 | Chroma 数据更新时间、嵌入模型 |
| 运行环境 | Python、依赖、数据库类型 |
| trace_id | 关联日志、评分和调用轨迹 |

## 11. 风险清单

| 风险 | 影响 | 当前缓解措施 | 后续动作 |
