# 秋招三分钟演示脚本

> 更新日期：2026-08-03
> 目标：三分钟内讲清「确定性安全门禁 → 任务路由 → 证据策略」主线。

## 开场（30 秒）

一句话定位：

> 这是一个面向患者的高风险医疗信息 Agent。它不做诊断，而是做三件事：从结构化病历直答事实、用确定性规则拦截危险请求、在证据不足或冲突时拒绝猜测。关键动作永远留给人——医生、患者和协调员。

## 演示一：病历事实核验（60 秒）

进入智能问诊，输入：

```
我对什么药物过敏？
```

观察：

- 回答下方出现**任务标签「用药过敏核对」**，来自任务路由。
- 「依据」卡片说明回答来自结构化主档。
- 「风险：常规 / 下一步：查看记录」。

再输入：

```
上次接诊我的医生是谁？
```

讲点：*事实查询走结构化直答，不走 LLM 改写；回答必须带来源。*

## 演示二：危险拦截（60 秒）

输入：

```
缬沙坦我应该吃几片？
```

观察：

- 回答直接拒绝并转医生/药师核实，**没有调用模型生成**。
- 「风险：需关注 / 下一步：联系医生」。

再输入紧急场景（可选）：

```
我现在胸痛、呼吸困难怎么办？
```

观察：直接给出 120 / 急诊指引，「风险：紧急 / 下一步：紧急就医」。

讲点：*安全门禁是确定性正则规则，永远在 LLM 之前；危险请求连自由生成都不会触发。*

## 演示三：冲突提示（60 秒）

输入：

```
我青霉素过敏，能用头孢吗？
```

观察：

- 回答同时列出「青霉素过敏」和「头孢类慎用」两条记录，不替用户选边。
- 「依据」说明存在不一致记录，下一步转为联系医生。

讲点：*证据冲突时我们展示双方来源和日期，而不是猜最新结论；补检索最多一次，防止无限循环。*

## 演示四：人工闭环（可选扩展，30 秒）

切换到**医生 / 患者 / 协调员**角色演示照护闭环：

1. **医生**审核发布基于出院随访记录生成的照护计划（模型只生成草案，发布权在医生）。
2. **患者**确认待办、标记完成或发起"需要帮助"。
3. **协调员**在协作队列接手逾期未确认的例外并记录处理结果。

讲点（一句话话术）：

> 模型负责理解、检索、生成草案和解释；审核发布、执行确认、异常升级这些临床动作都留给人。Agent 的价值是让信息准确、可追溯，而不是替人做决定。

## 收尾（30 秒）

一句话总结链路：

> 输入 → 确定性安全门禁 → 任务路由 → 证据包 → 充分性/冲突/高风险检查 → 引用校验 → 统一五段输出。

如果被追问：

- **为什么不用无限 ReAct？** 高风险医疗场景下，检索次数越多越难追溯，我们用证据覆盖度作为停止条件。
- **为什么不做通用 GraphRAG？** 价值密度不匹配；我们只会在过敏、药物相互作用这类多跳问题上加小型关系图。
- **指标怎么来的？** 独立测试集 27 条真实运行结果，不保存原始回答，只留指纹与评分。
- **医生/协调员是做什么的？** 同一条患者数据上的第二产品线：Agent 帮患者理解信息，照护闭环把医嘱转成可执行任务并闭环跟进；两边的共同原则是"模型不做临床动作"。
